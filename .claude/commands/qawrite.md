# 実行手順

## 0. 重要方針

- 書き込みには必ず MCP の「Notion」コネクタ（純MCP）を使用すること。
- claude.ai Notion コネクタは使用してはならない。
- Markdown文字列として貼り付けるのではなく、Notionブロック構造として追加すること。

---

## 1. 引数解析

- 第1引数を Notion URL として扱う。
- URLに `#` が含まれる場合：
  - `#` 以降を「セクション名（見出し名）」として扱う。
  - `#` より前をページURLとする。

例：
/qawrite https://notion.so/xxxx#repo-a

---

## 2. 書き込み対象QAの確定

- 直前の `/qa` 出力（チェックボックス形式のQAチェックリスト）を取得する。
- 直前にQAチェックリストが存在しない、または特定できない場合は停止し、以下を出力する：

「直前の /qa 出力が見つかりません。書き込みたいQAチェックリストをこのチャットに貼り付けてから、再度 /qawrite を実行してください。」

---

## 3. Notionページ取得（純MCP必須）

- MCP「Notion」コネクタを使用してページを取得すること。
- 取得できなかった場合は停止し、以下を出力する：

「Notionページにアクセスできませんでした（権限 / URL / 共有設定を確認してください）。」

---

## 4. 書き込み位置決定

### セクション指定あり

- ページ内のHeadingブロックを検索する。
- テキストがセクション名と完全一致するHeadingを探す。
- 見つかった場合は、そのHeadingブロックの children に追記する。
- 見つからなかった場合はページ末尾に追記し、先頭に以下を追加する：

「※指定セクション（{セクション名}）が見つからなかったため、ページ末尾に追記」

### セクション指定なし

- ページ末尾に追記する。

---

## 5. ブロック生成ルール（最重要）

### 見出し

- `## repo名` → Heading2 ブロックとして追加
- `### A. ...` → Heading3 ブロックとして追加

---

### チェックボックス（To-doブロック）

各QA項目は必ず以下の構造で生成すること。

#### 親チェック項目

- To-doブロック
  - checked: false
  - テキスト: テスト項目本文（優先度・環境・観点・期待を含める）

例：

- [ ] API契約が整合していること（優先度: 高 / 環境: staging / 観点: IF確認 / 期待: エラーが発生しない）

---

#### 子チェック項目（存在する場合）

- 親To-doブロックの children として追加する。
- 子も To-doブロック（checked: false）とする。

例構造：

親：
- [ ] 画面表示確認（優先度: 中 / 環境: local / 観点: UI / 期待: 正常表示）

子：
  - [ ] xxxが表示されること
  - [ ] yyyが表示されること

※ Markdownインデントではなく、Notionのブロック階層で構築すること。

---

## 6. インデント方針

- 原則2階層までとする。
- メタ情報（優先度など）は子ブロックに分離しない。
- 深いネストは作らない。
- すべて未チェック状態で追加する。

---

## 7. 追記前の区切り

追記の先頭に以下を追加する：

Heading2: QAチェックリスト（追記）

可能であれば生成日時も追記する。

---

## 8. 実行結果出力

成功時は以下を出力する：

- 「NotionにQAチェックリストを追記しました。」
- ページURL
- 追記位置（指定セクション配下 / ページ末尾）
- 追加したTo-do項目数

失敗時は、原因を簡潔に出力する（権限 / URL不正 / セクション未検出 / 接続エラー など）。
